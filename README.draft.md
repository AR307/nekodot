# nekodot

### 把你的 AI 小队，带到自己的电脑上。

nekodot 是一个基于 Hermes 的个人 AI 工作空间。为研究、写作、日常事务创建各有所长的 Bot，和它们单独交流，或把它们放进群聊一起完成任务。

从浏览器发出指令，在自己的电脑或服务器上执行。回复、工具进度、需要确认的操作和交付文件，都汇集在同一个界面里。

## 能用它做什么

| 能力             | 使用体验                                                                   |
| ---------------- | -------------------------------------------------------------------------- |
| 你的 Bot 小队    | 给每位 Bot 设置名字、头像、角色和模型，分别培养它们的工作习惯。            |
| 私聊与实际执行   | 流式查看回复、展开工具过程，在需要时确认操作、补充指令或停止任务。         |
| 群聊协作         | 用 `@handle` 指定成员，让研究、写作与核对依次接力。                        |
| 记忆与自我改进   | 查看和编辑 Bot 的原生记忆，调用 Hermes 的整理能力积累经验。                |
| 定时任务         | 在聊天中安排任务，在 Bot 详情中查看计划和执行记录。                        |
| 文件资料库       | 找回 Bot 交付的文件，预览、下载，或跳回当时的对话。                        |
| Skills 与插件    | 浏览 Hermes 扩展目录，选择安装到哪些 Bot，并管理启用状态与配置。           |
| 多电脑与多端同步 | 切换已配对节点，在不同浏览器中查看同一工作进度；刷新或短暂断线后继续查看。 |

### 一位 Bot，一个真正的 Hermes agent

每个 Bot 对应一个独立的 **Hermes profile**。模型调用、对话上下文、工具执行、记忆、技能和自我改进，直接使用 Hermes 原生实现。

nekodot 把这些能力整理成易于使用的产品界面，并负责电脑连接、消息同步与群聊接力。不同 Bot 的 profile 各自独立；同一 Bot 在私聊与群聊之间延续已有的原生会话上下文。

你可以把小研设为研究员，把笔笔设为编辑，让它们各用适合自己的模型和技能。名字、头像、角色与模型都能随时调整，已经积累的历史与记忆会保留。

### 在任务进行时，仍然能掌握进度

对话里既有回答，也有执行过程。工具卡片展示 Bot 正在做什么，审批卡片让需要确认的操作有明确入口。

- **看见过程：** 实时文本、工具开始与完成状态、等待确认状态集中展示。
- **补充指令：** 运行中发送新消息，由 Hermes 原生 steer 补充到当前回合，保留已经完成的工作。
- **确认操作：** 按当前 Hermes 权限设置处理审批；等待确认时可以继续编辑草稿。
- **主动停止：** 使用独立停止按钮取消当前执行。
- **回来继续看：** 刷新、切换页面或连接恢复后，同步历史与当前运行状态。

补充指令不会强行中断正在执行的工具，也不会撤销已经产生的结果；无法接收的指令会明确提示，并保留重新发送的入口。

### 把任务交给一个小组

一个群组可包含 **2–6 位 Bot**，并指定一位主答。没有指定成员时，由主答开始；输入成员的 `@handle`，就能决定谁先参与。

例如，让写作与研究分工完成一份周报：

> 这周的周报，@bibi 先整理草稿；@xiaoyan 帮忙核对数据来源。

Bot 可以在最终回复中继续 `@` 其他成员交接任务。界面按作者展示回复、头像和工具结果，并显示接力进度。每条用户任务最多执行 6 个 Bot 回合，同一群组按顺序处理，不同群组可以同时工作。

运行中补充新要求，仍交给当前 Bot 的同一个 Hermes run；接受后清空尚未执行的接力队列。需要结束整个协作时，点击「全部停止」。

### 每位 Bot 都有自己的工作积累

从 Bot 头像、名称或会话菜单打开详情，查看三个部分：

| 部分   | 你可以做什么                                                                                                               |
| ------ | -------------------------------------------------------------------------------------------------------------------------- |
| 详情   | 查看基本信息、定时任务、计划与执行记录；任务继续通过聊天创建和修改。                                                       |
| 记忆   | 查看、编辑 `SOUL.md`、`MEMORY.md` 与 `USER.md`，分别管理自身设定、长期经验和用户偏好；点击「整理记忆」调用原生 `/refine`。 |
| 资料库 | 搜索与筛选该 Bot 交付的文件，预览图片、PDF 和文本，下载文件或返回来源消息。                                                |

已经交付的文件会保存副本，原工作文件之后变化，不影响这次交付。私聊与群聊的文件按实际发送 Bot 归属；仍可读取的历史交付引用也可以补录。

### 通过 Skills 与插件扩展能力

在独立的 **Skills** 和 **插件** 页面浏览目录、阅读说明，再选择安装到当前电脑上的哪些 Bot。

- 查看官方、社区与本地来源，以及各 Bot 的实际安装状态。
- 阅读完整 `SKILL.md`，了解技能用途与使用方式。
- 从 Git 仓库或本地文件、目录、ZIP 导入扩展，保留配套脚本与参考资料。
- 按 Bot 启用或停用，并为插件填写所需配置与密钥。
- 查看 Hermes 返回的生效提示、缺少配置或重启要求。

技能、插件的安装与加载交给 Hermes；每个 Bot 的配置仍归属于自己的 profile。

## 开始使用

当前版本采用自托管 Relay 与本地开发网页。先由部署者准备 Relay 和网页入口，再按以下流程连接自己的节点。

1. **注册并登录。** 打开 nekodot 网页，创建账号。
2. **添加电脑。** 选择本机或云服务器，复制页面生成的一行安装命令，在目标环境执行。Windows 用户需在启用 systemd 的 WSL2 Ubuntu 24.04 中安装节点。
3. **等待上线。** 安装器完成节点安装、配对与服务启动后，网页显示电脑在线。
4. **连接模型。** 在提供方设置中选择 OpenRouter，或填写自定义 OpenAI-compatible API URL 与 API key，获取模型目录。
5. **创建第一位 Bot。** 设置名字、头像与角色，从模型列表选择，或直接输入模型 ID。
6. **开始工作。** 先发起私聊；需要协作时，创建群组并邀请其他 Bot。

安装节点当前支持 **Linux x64** 和 **WSL2 Ubuntu 24.04 x64**。节点使用项目专属目录和运行环境，安装与运行说明见 [部署文档](deploy/README.md)。

## 架构与数据

```text
浏览器 Web
    │ 账号、配对、消息与文件传输
    ▼
Relay
    │ 节点主动建立的连接
    ▼
Node · 你的电脑或服务器
    │ 官方 CLI / API
    ▼
Hermes · 每位 Bot 一个 profile
```

| 位置           | 保存和处理的内容                                                                             |
| -------------- | -------------------------------------------------------------------------------------------- |
| 浏览器         | 展示与交互；持久保存登录态、语言和选择项，聊天内容由节点同步。                               |
| Relay          | 保存账号与配对信息，负责认证、在线状态及连接路由；转发消息和文件，不持久保存聊天或文件正文。 |
| Node           | 保存聊天历史、运行记录、Bot 配置与交付文件，管理 Hermes 生命周期。                           |
| Hermes profile | 保存该 Bot 的原生会话、记忆、技能、插件及托管密钥。                                          |

完整提供方密钥保存在节点侧，网页查询只返回后四位。模型请求会发送到你配置的提供方；这套架构不等同于离线运行或端到端加密。

## 开发与部署

技术栈：**React 19 · TypeScript · Tailwind CSS v4 · motion · Zustand · Fastify · WebSocket · SQLite · Hermes**。

开发环境要求 **Node 24 LTS** 与 **pnpm 10.34.5**。

### 连接已部署的 Relay

在仓库根目录执行，SSH 参数使用本机已有的主机别名：

```sh
pnpm install --frozen-lockfile
pnpm dev:remote --ssh <your-ssh-alias>
```

该命令建立 SSH 隧道，在本机 `http://127.0.0.1:4318` 启动并打开网页。浏览器的 API、WebSocket 和安装包下载统一经网页同源代理；远端 Relay 保持监听 loopback。

需要从同一局域网的手机访问时：

```sh
pnpm dev:remote --ssh <your-ssh-alias> --lan
```

本地 Relay 开发、节点源码运行与验证命令见 [现有开发说明](README.md#开发)；Relay 镜像、安装器和系统服务见 [部署文档](deploy/README.md)。

### 仓库结构

