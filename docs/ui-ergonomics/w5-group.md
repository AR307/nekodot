# W5 群聊与接力

## 改动

- 新建群组不可用时说明原因（F11）：电脑离线或不足 2 个 Bot 时，侧栏群聊区显示原因文字，并以 `aria-describedby`/`title` 关联到禁用的「+」；不再是无解释的禁用。
- 失败与错误文字：新增 `--danger-text`（浅色 #ab3725、深色沿用 #ec7a63），用于危险色底纹上的文字（失败标签、表单错误）。真实群聊中失败标签由 3.86:1 提升到 ≥ 5:1。
- 探针：录制环境补充第二个 Bot 与一个群组，新建群组弹层与群聊界面在 4 组布局中均可达；`groups` 进入门禁。

## 真实环境验收（`tests/browser/ergonomics-live-group.spec.ts`）

通过产品界面在真实 Node 上新建第二个 Bot「小核」（ChatGPT 订阅 `gpt-6-sol`）与群组「核对小组」（主答 @1），随后发送真实群聊消息。两者保留在本机节点，可在界面中归档。

| 轮次 | 自己的消息 | 工作提示 | 接力标签 | 本轮结束 | 距底部 | 结果                                                                                  |
| ---- | ---------- | -------- | -------- | -------- | ------ | ------------------------------------------------------------------------------------- |
| 1    | 29ms       | 46ms     | 53.0s    | 113.4s   | 0px    | @1 回复并交给 @assistant；小核失败「Could not start this run…」，系统提示继续后续成员 |
| 2    | 49ms       | 75ms     | —        | 107.3s   | 0px    | 完整接力：@1 → 交给 @assistant → 小核回复                                             |

- 缺 Bot 时的说明文字、新建 Bot/群组弹层（焦点契约通过）、群聊界面、接力标签与头像上跳均符合设计板；第二轮无 P1/P2。
- 第一轮失败发生在小核新建后的欢迎消息仍在运行时；欢迎结束后第二轮成功。

## 产品发现（非界面人体工学，建议另行处理）

- F19：成员自身仍有运行（如新建后的欢迎消息）时，群聊接力直接失败而非排队等待。
- F20：该失败提示来自节点/Hermes 的英文原文，中文界面未本地化。
- F21：中文名「小核」生成的句柄为默认的 `@assistant`，未按名称派生；群里出现多个中文名 Bot 时 @ 会难以区分。
