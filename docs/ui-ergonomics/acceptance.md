# 人体工学验收与动效/排版系统：总验收报告（Web / Tauri 共用 React）

日期：2026-11-05。设计与准则：`docs/superpowers/specs/2026-11-05-ui-ergonomics-motion-design.md`；实施计划：`docs/superpowers/plans/2026-11-05-ui-ergonomics-motion.md`；逐项发现：`findings.md`；各波记录：`baseline.md`、`w1-foundation.md` … `w7-settings-screen.md`。

## 结论

- 共用 React 界面的全部功能面（账号、启动、配对、外壳与导航、命令面板、私聊与输入框、群聊与接力、Bot 新建/详情/记忆/资料库、Skills/插件、设置/授权/通知、屏幕面板）在真实环境与录制环境中均无 P0/P1/P2 发现。仅剩两项已记录的接受例外（F07 侧栏分隔条、F15 电脑菜单覆盖下方按钮）。
- 动效与排版由单一 token 来源驱动，4 项静态守卫在 CI 中拦截回退；全部界面在 11 项人体工学准则的自动探针中进入门禁。
- 真实模型验收通过：私聊与群聊接力均在真实 Relay / Node / 官方 Hermes / ChatGPT 订阅 `gpt-6-sol` 上完成。

## 工程门禁

- `pnpm lint`、`pnpm typecheck`、`pnpm test`（40 文件 / 75 项，含 4 项设计系统守卫）、Web 构建：通过。
- E2E（Edge）：23 通过、1 失败、10 跳过。改造前为 13 通过、6 失败。
  - 失败：`node-update`，W0 代码上同样失败——`/me` 加载时计算更新命令，测试节点之后才连上便不显示，属节点更新流程时序问题。
  - 跳过：需要私有会话文件的真实验收（本次另行运行并通过 9 项）与需要 Linux 节点的屏幕实测。
- 运行方式：私聊旅程需 `NEKODOT_BROWSER_RELAY_PORT=4359 NEKODOT_RELAY_URL=http://127.0.0.1:4359 PLAYWRIGHT_WEB_PORT=4421`，避开本机真实 Relay；真实验收使用 `NEKODOT_LIVE_ACCEPTANCE_FILE`（忽略目录内的私有文件）。
- 测试不再覆盖已提交的历史证据截图（`docs/evidence`）。
