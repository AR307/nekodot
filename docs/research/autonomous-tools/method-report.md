## 输入输出与最小算法

输入：问题 ID、8 条初始证据的 URL、短文本、支持方向及可观察来源字段，另有相同的 5 条候选元数据。候选正文和支持方向不供选择函数读取。输出：支持/反对/拒答、分数绝对值、是否补取一条及其索引。

```text
key(e) = observed_origin(e), if present; otherwise exact normalized text
within each key: average signed votes
score = average of group averages
if initial votes conflict and policy enables gating:
    fetch first candidate with known origin unseen among initial records
    fall back to rank 1 if none; never use hidden root or candidate vote
recompute score; predict its sign; zero means abstain
apply development-only acceptance threshold
```

注意：原型直接使用含错的可观察 origin 字段，不含生产级来源抽取、认证或可靠度筛选，因此尚不能称为已经实现了“保守来源发现”。没有将域名当独立来源。组内取平均保留相互冲突方向，但仍不能恢复独立提取的信息价值。

## 可复现设计

种子 271828，600 个合成问题，开发 200、测试 400，问题和潜在来源根完全隔离；来源根仅在评估文件和明确标注的 oracle 策略中读取。各问题 7 个潜在来源，假设来源回答正确概率 0.72；前 4 个来源按随机偏斜权重产生初始 8 条结果。初始排名、正文相似度及支持方向均为人为生成，不代表真实网络分布。候选池 5 条；普通策略取排名第一，定向策略取可观察新来源。候选元数据在实际系统中如何取得及其费用尚未模拟。

四条件：完整；每条以 0.6 概率缺失；以 0.6 概率误拆；以 0.6 概率误并。一次一个干预，不混合。10 个基线/消融：多数票、URL 去重、SequenceMatcher 文本去重、只分组、普通补取、只按来源新颖性补取、分组+普通补取、分组+新颖性补取、冲突门控组合、真实分组 oracle。URL 全部不同，这个基线在本生成器中退化成多数票；它不是针对 URL 去重的现实竞争性评估。文本模板很相似，0.94 阈值可能错误合并互相矛盾的句子，不能据此声称优于真实文本去重。

每个补取策略最多返回 9 条证据，候选元数据访问相同；未限制真实 token 数或模拟搜索调用延迟。因此当前只具有相同条数上限，不是严格等 token/美元比较。固定 80% 覆盖率诊断按无标签置信度排序选择 320 题；若出现零分平局，以问题 ID 哈希确定强制答案，并报告数量。该诊断不是预部署阈值承诺。独立部署评估在开发集选择观察错误率 <=0.1、至少回答 30 题的最大覆盖率阈值，无可行阈值则全部拒答；没有统计风险保证。

## 实际观察

下表均为固定 320/400 回答的错误题数；不是 LLM 或真实事实核验结果。

| 条件 | 普通补取 | 分组+普通补取 | 分组+定向补取 | 只分组 |
| ---- | -------: | ------------: | ------------: | -----: |
| 完整 |       64 |            45 |            41 |     58 |
| 缺失 |       64 |            57 |            59 |     63 |
| 误拆 |       64 |            59 |            60 |     65 |
| 误并 |       64 |            61 |            53 |     71 |

完整条件无 token 预算的组合取得较少错误，但缺失和误拆时定向补取不如同样分组的普通补取。只分组在误并条件比多数票更差：71 对 65。冲突门控平均补取 0.5275 次，但四条件均无可用开发阈值，测试全部拒答；不能将零错误当作收益。文本基线固定覆盖率包含 69 个强制平局，需保留这一说明。完整条件的分组+定向补取开发阈值在测试接受 256 题、错 24 题；这与其他方法覆盖率不同，不能直接横比其错误数量。

## 数学性质、假设与未验证结论

可证明的有限性质：对组内支持方向完全一致的某组，增加任意相同方向的副本不改变组均值，故不改变全体组均值及其符号，前提是来源键与组数不变。组内存在冲突时，增加同一方向副本会改变均值，不享有一般复制不变性。测试只对所列边界实例作执行检查，不等于形式化证明。

待验假设：可信来源信号可改善补搜收益；门控可减少检索且保持风险/覆盖；这些性质在真实模型抽取、真实网络和噪声元数据下成立。当前单种子生成器不验证它们，也不支持新颖性或显著性结论。

## 1–2 周真实实验建议及失败判据

先冻结公开、可核对的事实问题与快照，开发/测试按事实及来源根隔离，人工标注潜在来源仅用于评分。冻结模型版本、提示和正文截断顺序；记录所有初始检索及候选元数据获取成本。按独立来源缺失、误拆、误并分层，并加入自然噪声集。加入短声明+引用提示、调好开发阈值的文本基线及相同 token、调用、美元上限的普通补搜；按配对问题 bootstrap 报告风险-覆盖与成本曲线。所有检索提示、版本、输入输出、token 与费用账本存档。优先先跑小规模 pilot 再确定样本量，不用本合成收益估真实功效。

建议预算上限 50 美元是设计约束，不是已核实的供应商报价。按 600 题×6 个模型策略×每题最多 2 次模型调用计，最多 7200 次模型调用；可先共享冻结抽取减少重复成本。实际单次模型及搜索价格需另行核验，预留 10 美元给检索/复查，其余 40 美元按账本硬停止；如不足则先缩策略与样本，不能超支后宣称同预算。预计一周采集/标注与实现，第二周冻结测试/统计/失败分析，未承诺时间内完成标注。

失败：固定覆盖率和实际成本后组合不优于普通补搜；收益被简单去重/短提示解释；只在 oracle 中有效；开发阈值导致大幅拒答；误并伤害超过完整元数据收益；或收益跨种子/真实噪声不稳。当前已观察门控阈值失败及部分干预下定向补取劣于普通补取，应保留负面结果。
