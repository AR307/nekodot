# 可见任务通知与设备归属检查

## 实现

- Node 根据实际执行终态发出 Bot/群组名称与最终回复的纯文本预览。等待审批、等待回答和失败使用明确提醒；主动停止不发完成通知，群聊仍只在整条接力结束提醒一次。
- Relay 转发通知预览，不将正文写入投递去重表或日志。FCM 同时包含系统可见标题/正文及点击路由数据；按 UTF-8 实际载荷预算截断，避免长中文回复超出 4 KB。
- Flutter Android 使用官方 Firebase 注册/接收/点击接口；Windows 使用在线账号事件和原生通知。当前可见会话不重复显示；通知点击仅定位和同步，不批准、不发送消息。
- 首次启动解释用途并请求系统权限；拒绝后设置页提供指引。离线、权限或 Google 服务问题明确显示，不增加替代推送服务。

## 已复现的设备绑定归属问题

隔离 Relay 中创建两个真实认证账号。账号 A 注册通知设备后，账号 B 用相同 `deviceId` 或 token 提交注册，修复前 HTTP 200 且设备归属被覆盖。

修复在认证 HTTP 边界拒绝其他账号占用的设备标识或 token，返回 409；用户须先退出此前账号，服务端退出会解除关联。

复测：两个账号的两个抢占请求均 409；B 注销 A 的设备不生效；A 正常注册/注销、节点通知去重和未授权客户端隔离通过。新增测试先在原行为下得到「期望 409 / 实际 200」，再验证修复。
