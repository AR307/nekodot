# Auth page implementation plan

**Goal:** Apply the user's supplied split layout and animated paths to the existing nekoDOT account pages while keeping real email authentication.

**Architecture:** A presentational React shell receives existing localized copy and form children. The feature keeps authentication state and API calls. Flutter uses an equivalent layout with a separate path painter and its existing client.

**Tech stack:** React, TypeScript, Tailwind 4, Motion, shadcn-compatible Button/Input; Flutter Material and CustomPainter.

## Constraints

- Preserve the exact product name `nekoDOT` and the existing authentication endpoints and credential storage.
- Preserve useful copy; remove the secondary benefits list and technical route diagram.
- No placeholder social sign-in or fabricated testimonials. No remote artwork is needed for this SVG design.
- Respect reduced motion, keyboard access, narrow screens and desktop window controls.
- Keep all existing files, user data and local credentials. Do not publish or push.
