# 2026-11-06 定时任务结果接续与对话授权

## 本次实现

- 配置任务时由 Agent 解释需要授权的操作，在聊天里询问用户；用户用自然语言回答，由 Agent 通过 `hermes routine approvals JOB_ID --policy JSON` 保存。没有授权配置表单、按钮或公开配置 RPC。
- 支持 `ask`、`approve`、`deny`，以及时区、星期和跨午夜时段。未确认的新任务暂停；保存规则仅自动恢复因等待确认而暂停的任务，不改变用户主动暂停的任务。
- 保留实际执行时的原生审批卡，只允许本次或拒绝；不把一次 cron 审批扩散成整个 profile 的永久允许。时间规则在每次需要授权的动作处求值，而非只在任务开始时求值。
- 普通 cron 结果关联原生执行记录，后续新回合可以读取未包含的结果；也可从执行详情选择某次结果追问。原生已经投递的结果不重复插入，不改历史缓存，不重跑已完成工具。执行会话只读。
- 原生界面验收发现并修复：用户追问消息中的“查看执行”错误地把用户 ID 当 Bot ID，导致 Invalid RPC arguments；现在使用该私聊的 Bot。深色用户气泡中的结果链接同时恢复可读颜色。

## 实际环境

- Windows 原生 Flutter 候选，隔离 Node/Relay，真实 Hermes checkout（本地提交 `8ac43a3e2a`），真实模型 `gpt-6.1-sol`。非假 Hermes、非录制模型。
- Relay 为 `127.0.0.1:4459`；Node、Hermes home、profile 和输出文件都在本地隔离验收目录。正式服务器和现有产品 profiles 不变。
- Android 固定复用 `NekodotNativePhase3` / `emulator-5554`；模拟器和真机结果分别记录。

## Windows 实际结果

1. 模型用原生 cronjob 创建任务，主动询问授权。用户回答“吉隆坡时间白天 08:00—22:00 询问、晚上 22:00—08:00 拒绝”；模型通过插件 CLI 保存，原生配置读回一致。随后在聊天中改为全天询问。
2. 原生 `execute_code` 产生审批卡，允许一次后实际生成 UUID 并追加到文件，结果回到 Bot 私聊。首次结果为 `a6f30345e3cc45b78a81010e3c898cc9`。
3. 普通追问和 GUI 选定执行结果的追问都准确复述同一 UUID；验收当时只有一个执行记录和一行文件，没有重新执行。
4. 聊天改为默认拒绝，实际触发 cron；模型收到 execute_code 拒绝并返回具体原因，文件仍只有原来一行。原生回合正常完成不等于脚本执行成功，保留其拒绝输出。
5. 聊天改为默认允许，原生读回 approve；再次从客户端触发 cron，没有 cron 审批卡，文件仅新增一行 `61e7a58c31d149d4b92717b713a4053a`。
6. 最终任务暂停。总共三次实际执行：允许一次、拒绝、自动允许；文件只有两行。后续追问没有制造第四次执行。

本轮分段继续已确认的同一次记录，没有为通过测试重建或重放已经完成的任务。模型配置回读时额外请求了一次普通 terminal 审批，实际核对命令是读取任务元数据后允许一次；没有授予会话或永久允许。

## Android 模拟器实际结果

1. 在固定 `NekodotNativePhase3` 的 Flutter 候选界面创建任务 `da809955d468`。真实模型主动询问，收到用户回答后保存 Asia/Kuala_Lumpur 的白天询问、晚上拒绝规则，原生读回一致。
2. 在聊天改成全天询问，触发真实 cron，点击原生审批卡的允许一次；实际文件追加 `a275ed5e4ec846d9a5e1020b6fca2404`，结果回到私聊。
3. 普通追问和点击执行详情后选定结果的追问，都准确返回上述 UUID。核对当时仅一个执行记录和文件一行，没有重跑。
4. 聊天改为默认拒绝，触发后得到原生 execute_code 拒绝；实际文件仍一行。
5. 聊天改为默认允许，真实 CLI 已返回保存成功，原生读回 approve。随后模型停滞在额外回读工具调用，停止该普通聊天回合后继续；没有重发设置。再次触发 cron 不出现审批卡，文件追加 `345cdb068ed9476ea7236b1b3b621a8b`。
6. 最终任务暂停；原生执行记录三条、实际文件两行，模拟器集成旅程完成。未将取消的回读回合计作模型完整成功。

两端均从真实客户端 `/cron run` 即时触发原生定时任务，不是模拟调度或伪造结果；本轮没有等待一小时自动 tick。开发候选界面与最终 Release 构建分别验证。Android 中途因测试截图插件/详情懒加载定位问题重新连接同一个任务继续，没有重建任务或重跑第一次已完成的执行。
