# Node 自动更新：本地验收

日期：2026-10-31。范围：本地开发分支及隔离 WSL Ubuntu 24.04；没有 push、部署或连接生产 Node。

## 实现

- Relay 在 Node / 客户端握手时读取磁盘清单。仅时间戳旧版本收到更新；真实旧版 `1.0.0` 保持连接，通过客户端显示一次手动更新命令。
- Node 使用发布公钥检查签名与下载内容，执行语法检查后等待原生任务、群聊接力、欢迎和管理操作空闲。切换保存上一版、写入待确认标记并以 75 退出。
- 安装器生成的 launcher 负责首次启动确认及失败回滚；手动重装是明确恢复入口。旧清单和标记按用户授权移入本地回收目录，不永久删除。
- Flutter / Web 复用现有界面、离线恢复和同步机制。旧 Node 在线时显示可复制命令，恢复在线后刷新 `/me`；不执行远程 shell、不增加更新状态机。

## 实际安装与真实模型

建立独立 Linux 用户、源码检出、依赖、账号、数据库和 Hermes home。复用了本项目已有的官方 Hermes 源码及下载缓存；安装时官方 PM 在新用户下准备独立依赖。因此这是实际安装/服务验收，**不是无缓存首次下载的验收**。Node 使用固定 24.22.1，Hermes 核心没有修改。

测试密钥只位于忽略的私有运行目录。测试发布 v1 / v2 / v3 / v4 / v5 / v6 分别使用 `20261031010000` 至 `20261031060000`；不生成生产私钥。

| 使用场景         | 实际结果                                                                                                                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 真实旧 bundle    | 从头像扩展前的 `8c9a4b4931` 源码和其协议构建，不是只把新代码版本伪装成旧版。通过下载的 `install.sh` 和独立 systemd user service 启动；发布签名清单和连接客户端后仍保持在线，没有未知消息断线循环。 |
| 一次手动安装     | 同一 Node 身份、Bot profile、真实模型介绍和历史保留；Windows 原生客户端、Edge 同一页面均自动移除命令提示，未要求重新登录或刷新。复制的是实际安装命令。                                             |
| v1 → v2 忙碌等待 | 真实 Hermes 执行一次 `terminal` 的 45 秒等待命令。下载后进程及 v1 保持不变；工具完成、最终回复 `UPDATE_BUSY_DONE` 后才切换重启，v2 恢复在线，历史中一张已完成工具卡，未重跑任务。                  |
| v3 启动崩溃      | 签名且语法有效的测试包在启动时故意抛错。launcher 真实恢复 v2，记录 v3 为 rejected；再次客户端握手不反复安装该版本。                                                                                |
| 篡改与错误签名   | v4 下载内容不匹配清单、v5 清单签名错误，均记录拒绝；v2 继续提供 RPC。两次拒绝间显式重启测试服务以重置 10 分钟失败冷却，不缩短产品冷却。                                                            |
| 更高有效版本     | v6 更新后仍保留原 Node、profile 与 4 条原私聊消息；创建 `ghost` 非 dot 头像 Bot 成功。                                                                                                             |

实际安装还复现了现有管理后端占用相邻端口的情况。安装器现在同时检查 Runs 与相邻管理端口；本次在独立端口重跑成功，没有停止已有服务。
